## P0-A: Record-size repair
**Source of ≤2-byte limit:** Gödel prime ledger (`ledger/src/lrd_godel.c`, `lrd_godel.h`).
- `e_i = bij256(s_i) + 1` where bij256 maps a k-byte string to a number ~256^k.
- `L = ∏ p_i^{e_i}` therefore has bit length exponential in record length.
- Default `max_bits = 1<<23` refuses anything larger than ~2-byte items with `LRD_GODEL_E_TOOBIG`.
- Not caused by binary framing of LRD-REC-v1, FITS, AIR, or Agda bounds; it is the prime-exponent serialization.

**Implemented:**
- `LRD-ENV-v1` versioned length-delimited envelope (`ledger/include/lrd_env.h`, `ledger/src/lrd_env.c`).
  - Magic `LRD-ENV-v1\n`, version u8, flags u8, payload length u32 BE, payload.
  - Supports 0, 1, 2, 3, 255, 256, 1024, 65535, ... up to 64 MiB.
  - Rejects truncated, oversized, trailing garbage, bad version, bad magic.
  - SHA-256 of the exact canonical serialized bytes (commitment binding).
  - `lrd_env_is_legacy_rec()` detects old `LRD-REC-v1\n` so legacy decoding is preserved.
- `lrd_godel_append_envelope()`: builds the envelope, then appends a zero-length marker item so the Gödel product stays inside `max_bits`. The full payload is bound by placing the envelope SHA-256 into the existing `payload_sha256` field of the state record. Historical L values are never rewritten or reinterpreted.
- Test harness `tests/ledger/test_env.c` covers the size matrix and reject cases.
- Ledger Makefile updated.

**Not executed here:** full `make -C ledger` requires `libgmp-dev` and `libssl-dev`. Envelope logic is self-contained and will compile once the toolchain is present. Existing small-record tests remain unchanged.
